ATENÇÃO: Esta fase transforma o app de SPA offline para um sistema
com servidor. Requer decisão sobre hospedagem (VPS, Railway, etc.).

3.1  📋 Estrutura do backend
     - Servidor: Node.js + Fastify (leve, rápido)
     - Banco: SQLite via better-sqlite3 (arquivo em data/)
     - Estrutura de diretórios:
         data/           → arquivos .db
         server/         → código do servidor
         server/routes/  → handlers de API
         server/db/      → schemas e migrations

3.2  📋 Banco de dados (SQLite — data/)
     - data/users.db         → usuários e auth
     - data/training.db      → treinos, modos, passeios, rotas
     Tables principais:
       users(id, email, senha_hash, nome, criado_em)
       sessions(id, user_id, token, expira_em)
       training_log(id, user_id, data, tipos, notas)
       weights(id, user_id, data, peso, tipo)
       rides(id, user_id, ...schema atual...)
       workouts(id, user_id, mode_id, ...schema atual...)
       routes(id, user_id, nome, gpx_data, stats)

3.3  📋 Tela de cadastro de usuário
     - Campos: nome, email, senha (mín. 8 chars, maiúsc., minúsc.,
       número e símbolo), data nascimento, altura, peso, meta, bike
     - Validação client-side + server-side
     - Hash de senha: bcrypt (custo 12)

3.4  📋 Tela de login
     - Email + senha
     - Sessão via JWT (expira em 7 dias) ou cookie httpOnly
     - Botão "Esqueci minha senha" (placeholder por ora)
     - Redirecionamento automático se já autenticado

3.5  📋 Migração localStorage → API
     - Criar endpoints REST:
         GET/POST/PUT/DELETE /api/user
         GET/POST            /api/weights
         GET/POST/PUT/DELETE /api/rides
         GET/POST/PUT/DELETE /api/workouts
         GET/POST            /api/training-log
     - Módulo js/api.js: wrapper fetch com auth header
     - Manter Storage como cache local (offline-first)

3.6  📋 Atualizar PWA para funcionar offline com sincronização
     - Fila de operações pendentes quando offline
     - Sync ao reconectar (Background Sync API ou fallback manual)

4.1  📋 OAuth2 com Strava (server-side)
     - Registrar app em https://www.strava.com/settings/api
     - Flow: redirect → callback → trocar code por token
     - Guardar access_token e refresh_token no banco (users.db)
     - Renovação automática do token (expira a cada 6h)

4.2  📋 Funcionalidades úteis da API Strava identificadas
     ALTA prioridade:
       - GET /athlete/activities → listar atividades de bike
       - GET /activities/{id}    → detalhe (mapa, FC, cadência, watts)
       - GET /athlete/stats      → totais (km, tempo, elevação)
     MÉDIA prioridade:
       - GET /routes/{id}        → rotas salvas no Strava
       - GET /segments           → segmentos conhecidos
     BAIXA prioridade (complexidade alta):
       - WebHook de atividade    → receber push ao salvar no Garmin

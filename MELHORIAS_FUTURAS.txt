CONTEXTO
A Garmin não disponibiliza API REST pública para usuário final — a
"Connect Developer Program API" é restrita a parceiros comerciais.
Para acessar dados do Garmin Connect é preciso recorrer a wrappers da
comunidade que simulam o app móvel (SSO + endpoints internos).

AVALIAÇÃO — projetos candidatos

[A] python-garminconnect (cyberjunky)
    - Wrapper Python puro, autenticação SSO + MFA, baixa atividades em
      .fit/.gpx/.tcx, lê HRV, sono, stress, body battery.
    - Manutenção semanal (alto, mas dependente de não-quebrar quando a
      Garmin mexe no servidor SSO).
    - Encaixe no nosso stack: REQUER subprocesso Python rodando ao lado
      do Node — adiciona dependência de runtime e empacotamento.

[B] GarminDB (tcgoetz)
    - Foco em data engineering: baixa histórico completo e materializa
      em SQLite local com tabelas analíticas (laps, splits, monitoring).
    - Inclui parser FIT nativo e templates Jupyter.
    - Encaixe: MUITO PESADO para uso embarcado — pensado para análise
      offline em notebook. Útil como referência de schema, não como
      dependência runtime.

RECOMENDAÇÃO
Usar [A] python-garminconnect via subprocesso isolado, expondo um
script CLI Python que o backend Node chama on-demand. Motivos:
  - Mantém Node como única superfície de API exposta
  - python-garminconnect tem manutenção ativa e cobertura completa
  - Dá pra rodar dentro do mesmo LXC (prod) sem novo container
  - Erros do SSO ficam confinados ao script Python (não derruba Fastify)

Alternativa descartada: portar a lógica SSO para Node — caro e
sujeito a manutenção contínua quando a Garmin mexer no fluxo.

REGRAS DE FONTE DA VERDADE (resumo)

  1. Edicao manual SEMPRE prevalece (lock implicito por campo)
  2. Entre fontes automaticas: Garmin > Strava (Garmin tem mais
     metricas brutas; Strava as recalcula)
  3. Para o mesmo campo de fontes diferentes sem lock manual,
     o sync mais recente sobrescreve
  4. training_log antigo (so com tipos[]) continua valido —
     daily_record o estende, nao o substitui

RISCOS / CONSIDERAÇÕES

  - Mexer no schema de training_log impacta o calendario, badges
    e mini-relatorio 90 dias — testar com cuidado
  - Auto-registro silencioso pode mascarar dias sem treino real
    (usuario esquece celular ligado no carro -> Strava registra
